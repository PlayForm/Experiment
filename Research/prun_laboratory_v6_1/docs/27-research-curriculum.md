# Research curriculum as deterministic software, not a school run by agents

The research program can feel like a creative school to the implementors, but
its **lesson assignment, prerequisite assessment, tests, grades, repetition,
resource allocation and release decisions are software**. Its objective is
diverse independently testable software discoveries, not schooling models to
maximize economic rewards or minimize tokens.

## Curriculum records

- `v61-curriculum`: signed owner-approved repository cohort, baseline commit,
  challenge families, trusted oracle, diversity and sealed evaluation rules.
- `v61-study-assignment`: one independent research track, one constrained source
  view, one local task description, output classes and fixed assignment rule.
- `v61-study-outcome`: facts from trusted oracles and runner, not the model's
  grades or assertions. A lesson may be `inconclusive`; that is retained as an
  outcome.
- `v61-physical-allocation`: CPU/GPU, memory, storage, dedicated benchmark
  slots, assigned by resource scheduler. Resource capacity prevents contention
  but is excluded from software performance scores.

## Challenge families

`exploration`: identify unexplained bottlenecks; `implementation`: implement one
hypothesis; `skepticism`: propose failure modes; `test-design`: propose edge
cases; `replication`: independently test a claim; `hardware-specialization`:
optimize a known target cohort; `cross-repository-transfer`: propose but do not
claim transferred benefits; `publication`: propose a private research narrative.
The model receives only a generic Rust source task and permitted references, not
the curriculum catalog or institutional arrangement.

## Pedagogy without LLM control

The curriculum software may pre-register a finite ordered set of task templates
and assign them by deterministic rules over observed state (unexplored symbols,
previous correctness failures, hardware cohort, repo source scope, model lineage
and membership in non-trading groups). It cannot ask a model which lesson should
run next, cannot use model self-reported scores for progression, and cannot
allow research papers to become experimental evidence without signed independent
measurement.

Each 'student' can maintain distinct hypotheses in its own encrypted
correspondence and local task history. Siblings are not permitted to exchange
drafts, artifacts or verdicts unless a signed declassification permits a
specific sanitized knowledge card. Same-family model overlap is explicitly
recorded; this is intellectual plurality, not an assertion of statistical
independence.

## Why it can produce emergent improvement

Variation arises from the proposals. Fixed truthful experiments evaluate them.
The independently preserved Pareto set becomes the allowed next reference
source. Continued research over accepted implementations can resemble inherited
evolutionary improvement, but no mutation/crossover algorithm or model-directed
fitness function is installed.

## Anti-monopoly policy

Control assignment overlap, repository access and trade graph edges via signed
policy: e.g. cap how often one research group gets the same source symbol,
reserve independent skeptic/replication slots, prevent relatives from sharing
private views, use independent runners for confirmation, and retain unpopular or
null hypotheses. Such fairness controls must never override correctness or
re-label slow software as fast.
