# Evolution without an explicit genetic algorithm

## The environment, not an algorithmic genotype optimizer

A branch or patch is not declared a chromosome. A change that compiles is not
automatically a useful mutation. The software substrate maintains multiple
immutable reference/candidate lineages, each with exact
source/build/workload/hardware identity. Proposal generators may produce
anything within their scoped worktree. Software converts admissible proposals
into tests against a pinned baseline. Candidates passing behavior constraints
join a workload/hardware Pareto set; some are preserved as specialists and
others become eligible as future parental snapshots. No agent picks winners.

This is **open-ended proposal search with deterministic evidence-based
selection**, not formally an encoded genetic algorithm. It might evolve
solutions through repeated differential survival and reuse. To avoid
self-deception, the observatory must report actual diversity, novelty, survival,
convergence, regression and transfer outcomes without claiming Darwinian or
optimal behavior merely because agents iterate.

## Atomicity and independence

- Each researcher has an immutable `research-track` record with private opinion,
  exact authorized source view, model-lineage fingerprint, task family, and
  parent track. A researcher's _opinion_ can never be a benchmark artifact.
- Each implementor sees a pinned source tree plus scoped task. It may inspect
  and locally compile/run Rust within an unprivileged offline sandbox. Local
  execution results are **worker claims** only.
- The trusted source adapter builds a baseline in its own isolated builder. The
  correct reference contract is established **before** giving an experimental
  problem to a patcher.
- Proposed tests enter a quarantine test-candidate index; they cannot change
  trusted oracle inputs. Promotion into trusted test corpus is a separate
  policy-validated source-controlled process and does not affect the cohort used
  to judge that same patch.
- Disparate source changes in one patch create one _compound_ candidate until
  decomposed and independently measured. A decomposition can be proposed by a
  model but the actual planned test combinations are generated by fixed software
  rules.
- Sibling research tracks are blind to one another's private output and
  evaluation. An independent replicator may receive a preauthorized hypothesis
  and independently controlled workload, but not experimental outcome before
  committing its preregistration.

## Diversity without economic gaming

There is no unrestricted agent marketplace or model-to-model barter. Define a
signed `trade-restriction` graph: groups A and B may be mutually embargoed for
an interval, and no lateral messages or artifacts cross that edge. A separate
software assignment policy can enforce maximum sibling overlap, minimum role
diversity, source-view separation, and independent confirmation. It may publish
aggregate anonymous progress counts only when a disclosure rule explicitly
authorizes them.

A single underlying LLM shared by all workers creates correlated priors. Prompt
roles and separate containers do not guarantee independent statistical evidence.
Record prompt-template versions and model lineage, and require evidence
replication from a separate runner/host and, where meaningful, independently
implemented tests.

## What constitutes successful inheritance

A candidate inherits only a verified source tree, declared feature selection,
explicit provenance, and rights-compatible approved knowledge. It does not
inherit a sibling's hidden conversations or a priori performance assertions. A
specialist fast path may become a new selectable strategy only after the runtime
dispatcher plus its analysis overhead is tested end-to-end.

## Instrumentation

Record per-source-symbol experiment counts, independent hypothesis coverage,
duplicate-patch rates, measured effect sizes, rejected/inconclusive results,
siblings' structural similarity (computed in trusted service without revealing
each other's patches), and propagation rights. None of those metrics is fed to
the agent unless explicitly part of a declassified, sanitized feedback view.

## Counterfactual

Run at least three campaigns under the same benchmark policy: (A) independently
generated patch sets, (B) source hotspot seeded tasks, (C) fixed
software-generated intervention opportunities. This measures whether the
_research environment_ yields better software without writing a dedicated GA,
and does not optimize agent token cost.
